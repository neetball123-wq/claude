# 音質リファイナー

曲を通すだけで音質を補正する Web アプリです。インストール不要で、iPhone の Safari でもそのまま動きます。
処理はすべて端末内（Web Audio API）で行い、音声をどこかへ送信することはありません。

## できること

| 機能 | 中身 |
| --- | --- |
| 高域補完 | 5kHz 以上の成分を全波整流して倍音を作り、10kHz 以上だけを足し戻す。MP3/AAC で削られた 16kHz 以上を埋め直す（SBR や DSEE と同じ系統の考え方） |
| 明瞭度 | 300Hz のこもりを抑え、3.2kHz の存在感と 10.5kHz 以上の空気感を上げる |
| 低域 | 95Hz のローシェルフと、140Hz 以下から作る倍音（小さなイヤホンでも低音が聞こえる） |
| ステレオ幅 | 180Hz 以上のサイド成分だけを強める。低音は中央に残る |
| 空間 | スピーカー配置のクロスフィード（0.27ms・1.1kHz ローパス）と、合成した部屋の響き（初期反射＋約 1 秒の残響） |
| 迫力 | ゆるいコンプレッサーで密度を上げる |
| 出力保護 | 瞬時アタックのピークリミッター（上限 −1dBFS）＋ソフトクリッパー。どの設定でも音割れしない |

- 再生しながら「原音」と「リファイン」を瞬時に切り替えて聴き比べ（処理遅延は原音側で補正済み）
- 「音量をそろえて比べる」：K 特性で測ったラウドネスをリファイン側に合わせ、音の大きさにだまされない比較にする
- 原音とリファイン後のスペクトルを重ねて表示
- 曲全体を 16bit WAV で書き出し
- **ライブ入力**：マイク・入力機器（iPhone 可）、パソコンのゲームの音、ゲーム機の音、パソコンの Chrome / Edge で流しているタブの音（YouTube、Spotify Web Player など）をその場で処理

## ゲームの音をリファインする

ブラウザは他のアプリの音を直接取れないので、ゲームの音を仮想オーディオに流し、このページがそれを受けて処理し、ヘッドホンに出します。

| 環境 | 準備 |
| --- | --- |
| Windows | 無料の [VB-CABLE](https://vb-audio.com/Cable/) を入れ、設定 → システム → サウンド → 音量ミキサーでゲームの出力デバイスを「CABLE Input」にする |
| Mac | 無料の [BlackHole 2ch](https://existential.audio/blackhole/) を入れ、システム設定 → サウンドの出力を「BlackHole 2ch」にする |
| Switch・PS5・Xbox | キャプチャーボードかオーディオインターフェースでパソコンに音を入れ、入力機器として選ぶ |
| iPhone・Android | 端末の中では他アプリの音を加工できない。イヤホン端子からケーブルでパソコンの入力へつなげばパソコン側で処理できる |

準備ができたら Chrome か Edge でページを開き、「ライブ入力 → ゲーム・パソコンの音」を押します。入力の一覧から仮想オーディオを自動で選ぶので、出力にヘッドホンを選べば完了です。

入力も出力も仮想オーディオになっていると、自分の出力がまた入力に戻って音がループします。その状態を見つけると自動で消音し、出力をヘッドホンに変えるよう表示します（出力先を選べない Safari や Firefox では、仮想オーディオを入力にした時点で消音します）。

## 遅延について

コンプレッサーとリミッターは先読みなしの AudioWorklet で自作しているため、**処理による遅れは 0 サンプル**です（テストで実測）。
ブラウザ標準の DynamicsCompressorNode は先読みで 6ms ずつ、計 12ms 遅れるので、AudioWorklet が使えない環境でだけ自動的にそちらへ切り替わります（原音側も同じだけ遅らせて聴き比べがずれないようにしています）。

残る遅れは端末の入出力バッファで、画面の「遅延（推定）」に表示されます。Bluetooth イヤホンはそれ自体に 0.1〜0.2 秒ほどの遅れがあり、ブラウザからは測れません。遅延を最小にしたいときは有線イヤホンを使ってください。

## 使い方

`index.html` をブラウザで開くだけです。ローカルで配信する場合：

```sh
npm start   # http://localhost:8080
```

最初は内蔵のデモ曲（合成音を MP3 128kbps 相当に劣化させたもの）が読み込まれています。「自分の曲を開く」から MP3・m4a・WAV などを選べます。

ライブ入力はマイクを使うため、https の通常の Web ページとして開く必要があります（Claude のプレビュー画面の中ではマイクや画面共有が使えません）。GitHub Pages で公開する場合：

1. リポジトリの **Settings → Pages** を開く
2. **Source** を「Deploy from a branch」、ブランチをこのアプリがあるブランチ、フォルダを `/ (root)` にして保存
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます（iPhone ではホーム画面に追加するとアプリのように使えます）

## できないこと

- iPhone で Apple Music や Spotify アプリが再生中の音には、リアルタイムでもかけられません（iOS は他アプリの音を加工する仕組みを公開していないため）。パソコンなら、ブラウザで再生している音をタブ共有で処理できます。DRM 付きの曲も読み込めません。
- 空間はヘッドホン向けの処理です。頭の向きに合わせた追従（ヘッドトラッキング）はしません。
- 高域補完は失われた音を推定して作り直す処理で、元の録音を完全に復元するものではありません。

## 検証

実際の Web Audio グラフをヘッドレス Chromium でレンダリングし、FFT で効果を測ります。

```sh
npm install
npm test
```

主なチェック：疑似デバイスでゲーム入力の自動選択・音ループ時の消音と解除・入力の切り替え／処理遅延が 0 サンプル（標準ノード使用時は申告どおり 12ms）／16〜20kHz が補完される／補完量が自然な範囲に収まる／各つまみが狙った帯域・広がりを変える／最大設定＋爆音素材でも −1dBFS 以下／書き出しの時間ずれがない／ZIP・WAV の形式が正しい／疑似マイクでライブ入力が動く／画面がスマホ幅に収まる。
